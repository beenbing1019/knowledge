# DDoS 防護策略

**問題**：分散式阻斷服務攻擊（DDoS，Distributed Denial of Service）讓大量來源同時送請求。例如售票網站突然被無效流量灌滿，真正的買票者無法連線。

**原因與影響**：攻擊可能耗盡上游頻寬、連線容量或應用運算資源。攻擊壓滿的是哪一層，決定防護要放在哪一層。只增加後端機器，救不了已塞滿的入口頻寬。

## 先讓服務撐住

1. **辨識瓶頸**：監控流量來源、錯誤率、連線數及上游頻寬；區分惡意流量和促銷活動的真實流量。
2. **上游清洗**：與網路服務供應商或 DDoS 防護服務合作，在流量進入自家網路前過濾大量攻擊。負載平衡可分攤正常負載，無法取代上游清洗。
3. **應用層限制**：依請求特徵限流；適當使用網站應用程式防火牆（WAF，Web Application Firewall）與驗證。只按 IP 封鎖可能誤傷共用網路中的真實使用者。
4. **隔離與降級**：保留登入、結帳等核心功能，必要時暫停高成本搜尋。多地部署可降低單地故障影響，但不能保證攻擊消失。
5. **演練與復原**：事先約定告警與聯絡窗口。備份可協助資料復原，不能緩解正在發生的流量攻擊。

黑洞路由會連合法流量一起丟棄，只適合保護上游網路的緊急情況，**不能**當作維持被攻擊服務可用的方法。保存必要日誌，供事後調查。
