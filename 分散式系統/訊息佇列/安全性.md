# 訊息佇列安全性

**問題**：佇列裡有訂單與聯絡資料。若測試用帳號能讀取正式環境的佇列，資料可能外洩；若能寫入，還可能偽造訂單事件。

**原因**：共用帳號、過大的權限、開放對外的管理介面，或未加密的傳輸，都可能讓不該存取的人接觸訊息。

**影響**：資料被讀取、訊息被竄改或重複送入，消費者可能執行錯誤操作。

**防護**：

1. **驗證與授權**：每個服務用獨立身分，只授予必要的佇列或主題讀寫權限。存取控制清單（ACL，Access Control List）可用於細分權限。
2. **保護傳輸**：使用傳輸層安全性協定（TLS，Transport Layer Security）加密連線，並驗證對端憑證。需要防範 broker 管理者讀取內容時，再評估訊息內容端到端加密與金鑰管理。
3. **限制網路入口**：只開放必要服務與管理員的連線；管理介面不要直接曝露在公網。
4. **處理重放**：若同一事件被再次送入會造成損失，以事件識別碼與消費端冪等檢查去重。時間戳只能限制有效時間，不能單獨阻止重複執行。
5. **監控與維護**：記錄登入、權限變更與異常流量；避免把敏感訊息內容寫入日誌。定期更新與修補 broker。
