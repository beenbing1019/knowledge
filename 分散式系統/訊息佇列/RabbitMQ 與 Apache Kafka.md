# RabbitMQ 與 Apache Kafka

兩者都能傳遞訊息，但擅長解決不同問題。先看訊息要被處理一次、分發給多方，還是保留供日後重播。

| 面向 | RabbitMQ | Apache Kafka |
| --- | --- | --- |
| 核心模型 | 交換器（exchange）依規則路由到佇列（queue） | 分區（partition）組成的追加日誌（log） |
| 消費方式 | 同一工作佇列的消費者競爭處理訊息 | 消費者群組（consumer group）用位移量（offset）追蹤進度 |
| 常見需求 | 工作分派與彈性路由 | 事件串流、保留與重播 |
| 注意事項 | 訊息確認、佇列容量及重試策略 | 分區鍵、保留期限與儲存容量 |

例如訂單成立後，若只需安排一位工作者寄出通知，可用工作佇列。若風控與報表都要讀取同一批訂單事件，還需重播過往事件，可考慮 Kafka。RabbitMQ 也能發布／訂閱；Kafka 也能分派工作，選型不只看產品標籤。

效能取決於批次、訊息大小、持久化、確認設定與負載。兩者都要設計複製、確認及消費端去重；不能只憑產品名稱保證不遺失、不重複。用實際需求與服務等級目標（SLA，Service Level Agreement）測試。
