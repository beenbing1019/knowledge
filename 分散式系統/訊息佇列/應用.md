# 訊息佇列的應用

訊息佇列適合把「先記錄、稍後處理」的工作分開，但不會自動讓工作成功。

| 場景 | 常見做法 | 要注意什麼 |
| --- | --- | --- |
| 訂單事件 | 下單後通知庫存、報表與會員服務 | 多個服務各自處理，失敗須重試與去重 |
| 背景任務 | 排隊產生報表或縮圖，交給多位工作者 | 任務可能重複執行；監控積壓與處理時間 |
| 通知 | 排隊寄信或推播 | 發送失敗需重試，避免重複通知 |
| 日誌收集 | 集中收取多個服務的事件 | 尖峰時處理容量與保留期限 |
| 分散式計算 | 把工作切成任務交由多台機器處理 | 需要追蹤結果、失敗與任務歸屬 |

例如購物網站結帳時，**付款與確認訂單**應先有明確結果；寄信可非同步處理。若資料庫已提交訂單，但訊息尚未送出時服務當機，可能漏寄。需要跨兩者可靠銜接時，可評估交易式 outbox：先在同一筆資料庫交易記錄待發事件，再由工作者送出，消費端仍要處理重複。
