# 訊息佇列基本原理

訊息佇列讓送出工作的**生產者**與執行工作的**消費者**分開。訊息代理（broker）先收下訊息，消費者再按自己的速度處理。訊息內容可以是文字、JSON（JavaScript Object Notation）或二進位資料。

例如網站收到訂單後，先記錄訂單，再把「寄確認信」放入佇列。寄信服務暫時變慢時，使用者不必一直等它完成。但「已放入佇列」不等於「已寄出」，畫面應顯示正確狀態。

- **非同步**：送出訊息後可先繼續工作；若需要結果，另設狀態查詢或回覆機制。
- **解耦**：寄信服務可以獨立部署；但雙方仍須約定訊息格式。
- **緩衝尖峰**：訊息可排隊等待；若進入速度長期高於處理速度，積壓仍會持續增加。
- **故障處理**：持久化、確認、重試與去重都要設計。送進佇列本身不保證不遺失或不重複。
