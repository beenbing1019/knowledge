# Redis 記憶體淘汰

**問題**：Redis 接近設定的 `maxmemory`，新資料放不進去。選哪種 `maxmemory-policy`，決定是否淘汰舊鍵，以及哪些鍵能被淘汰。

```text
maxmemory 1gb
maxmemory-policy allkeys-lru
```

- `noeviction`：需要更多記憶體的寫入可能回錯，不代表所有命令都失敗。
- `allkeys-lru`：從全部鍵中，近似挑選最久未使用的鍵。
- `volatile-lru`：只從有過期時間的鍵中，近似挑選最久未使用的鍵。
- `allkeys-random`：從全部鍵隨機挑選。
- `volatile-ttl`：從有到期時間的鍵中，優先挑剩餘時間較短者。

例如把登入狀態與商品快取存在同一 Redis，若使用 `allkeys-lru`，登入狀態也可能被淘汰。要按業務重要性隔離資料或設計合適策略。`volatile-*` 沒有可淘汰的到期鍵時，寫入也可能失敗。

策略值必須寫完整；`LRU`、`TTL`、`Random` 單獨都不是設定值。用 `INFO memory` 觀察用量；鍵空間通知（`notify-keyspace-events`）是事件訂閱，不是記憶體分析器。

參考：[Redis 官方：Key eviction](https://redis.io/docs/latest/develop/reference/eviction/)。
