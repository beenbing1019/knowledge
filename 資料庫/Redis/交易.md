# Redis 交易

`MULTI` 把命令排隊，`EXEC` 再依序執行；期間不插入其他客戶端的命令。這**不是**可以回滾已執行命令的 SQL 交易。

```text
MULTI
SET foo 10
INCR bar
EXEC
```

- `EXEC` 前用 `DISCARD` 可放棄排隊命令。
- 排隊時語法出錯，`EXEC` 會拒絕執行該交易；執行時某命令出錯，其他命令仍會執行。須檢查 `EXEC` 每項回覆，不能假設全部成功。
- `WATCH` 是樂觀鎖：在讀鍵前先監看。若鍵在 `EXEC` 前被修改，交易不執行，客戶端可重新讀取並重試；其他客戶端不會被阻塞。

例如庫存存在 Redis，兩位顧客同時讀到 1 再各自寫成 0，會多賣一件。單純 `MULTI` 不能保護交易前的讀取；先找適合的原子命令，或用 `WATCH`／`MULTI`／`EXEC` 偵測衝突。關鍵庫存仍須考慮最終資料庫的約束。

參考：[Redis 官方：Transactions](https://redis.io/docs/latest/develop/using-commands/transactions/)。
