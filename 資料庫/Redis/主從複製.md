# Redis 主從複製

主節點（primary）把資料同步給複本（replica），可分攤部分讀取與支援故障切換。**複製是非同步的**：讀複本可能讀到舊資料，切換也可能失去尚未同步的寫入。

- **全量同步**：主節點傳 RDB 快照，再補上快照期間與之後的命令；與是否啟用 AOF 是兩回事。
- **部分重新同步**：斷線重連時，依複製識別碼（replication ID）與位移量（offset），從複製積壓緩衝區（replication backlog）補資料。若緩衝區不足，須再做全量同步。
- **過期鍵**：主節點控制過期，並將刪除事件傳給複本。`repl-diskless-sync` 只改變全量同步的傳輸方式，並非過期鍵過濾器。

例如首頁讀取複本顯示庫存 1，但主節點剛賣完最後一件；若業務不能接受舊值，需從主節點讀取或另設一致性控制。Sentinel 或 Cluster 可協助切換主節點，但客戶端仍要能找到新主節點。複本不是獨立備份。

監控複製延遲、斷線與緩衝區容量；`repl-backlog-size` 要按寫入速率與預期斷線時間設定。

參考：[Redis 官方：Replication](https://redis.io/docs/latest/operate/oss_and_stack/management/replication/)。
