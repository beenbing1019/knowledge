# Redis 故障排除

**術語**：AOF＝附加式檔案（Append-Only File）；RDB＝Redis 資料庫快照（Redis Database）；LRU＝最近最少使用（Least Recently Used）；TTL＝存活時間（Time To Live）。

先確認影響範圍，再依「不能連、變慢、資料不見」分頭查；不要在原因不明時直接重啟或修復持久化檔案。

| 現象 | 先查什麼 | 常見原因與處理 |
| --- | --- | --- |
| 無法啟動 | Redis 與系統日誌、設定、磁碟、記憶體 | 設定錯誤或資源不足；若持久化檔案疑似損壞，先備份原檔，再依官方程序檢查 `redis-check-aof`／`redis-check-rdb` |
| 客戶端連不上 | 服務狀態、`bind`、防火牆、驗證 | 連錯節點、網路封鎖或帳號無權限；不要為測試直接對公網開放連接埠 |
| 變慢 | `INFO`、`SLOWLOG`、中央處理器（CPU，Central Processing Unit）、網路與 AOF 重寫 | 慢命令、大鍵、負載或持久化成本；先量測再調整 |
| 資料遺失 | RDB／AOF 設定、淘汰紀錄、複製延遲 | 過期、淘汰、持久化窗口或切換；用獨立備份復原，並查根因 |
| 寫入失敗 | `INFO memory`、`maxmemory`、淘汰策略 | `noeviction` 或缺少可淘汰鍵；預留複製與持久化所需的額外記憶體 |

例如促銷時購物車突然寫不進去，先查 `maxmemory` 與 `maxmemory-policy`。合法策略值如 `allkeys-lru`、`volatile-ttl`；`LRU` 或 `TTL` 單獨使用不是有效設定。設定上限也不表示整個 Redis 程序絕不超出該數值。

若工作者拿不到分散式鎖，先查租約與持有者；多人競爭同一把鎖本身不叫死鎖。修復後驗證請求、資料與告警是否恢復。

## 同樣是「讀不到」，處理不同

- 連線失敗：先確認 Redis 程序、連線埠、網路與存取控制清單（ACL，Access Control List）；不要為了測試關閉驗證或對外開放埠。
- 連得上但鍵不存在：查 TTL、淘汰與複本延遲；重啟不能讓已淘汰的鍵回來。
- 回覆很慢：查大鍵、`SLOWLOG`、持久化與主機負載；可拆大鍵、調整命令或管線化，但先量測瓶頸。

碰到持久化檔案疑似損毀，先複製原檔並確認有獨立備份，再按官方程序檢查；不可直接就地改寫唯一副本。

參考：[Redis 官方：Troubleshooting](https://redis.io/docs/latest/operate/oss_and_stack/management/optimization/)。
