# Redis 資料型別

Redis 的鍵會對應一種資料型別。先想「要怎麼讀寫」，再選型別。

| 型別 | 特性 | 常見用途 |
| --- | --- | --- |
| 字串（String） | 保存文字或二進位資料；可用 `INCR` 計數 | 快取單一值、計數器 |
| 列表（List） | 元素有先後順序，可重複，兩端可推入或移除 | 簡單任務列表、歷史紀錄 |
| 雜湊（Hash） | 一個鍵包含多個欄位與欄位值 | 使用者資料的部分欄位 |
| 集合（Set） | 不排序、不重複；支援交集等操作 | 已按讚的使用者編號 |
| 有序集合（Sorted Set） | 每個成員有分數（score），可依分數排序 | 排行榜、時間序列索引 |

例如「誰按讚過這篇文章」適合用 Set 避免同一人重複出現；「本週最高分前十名」可用 Sorted Set。若任務需可靠的確認、重試與消費者群組，不能因 List 能當簡單佇列，就假設它具備完整訊息佇列保證。
