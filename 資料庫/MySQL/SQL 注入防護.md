# SQL 注入防護

**問題**：網站把使用者輸入直接接在 SQL 後面。例如登入頁用字串拼出查詢；有人輸入 SQL 語法，可能改變原本的查詢條件。

**原因**：程式把「資料值」當成 SQL 指令的一部分。結果可能是繞過驗證、讀取不該看的資料，或在權限過大時修改資料。

**阻擋方式**：

1. 對資料值使用**參數化查詢／預處理語句**。SQL 結構與使用者提供的值分開處理；不要用字串插值拼接。
2. 表名、欄名與排序方向無法當作一般值綁定。若要讓使用者選排序欄位，從程式內建的允許清單選取。
3. 資料庫帳號只授予必要權限。輸入驗證可減少不合法輸入，但不能取代參數化。

例如商品頁允許按價格排序，只接受程式定義的 `price`、`created_at` 兩個欄位；搜尋關鍵字則交給參數綁定。不要把關鍵字或欄位名稱直接接進 SQL。
