# 轉帳與 ACID

A 轉 100 元給 B，必須避免「A 扣了錢，B 卻沒收到」。交易的 ACID 是四個不同的性質，不代表應用程式不用處理業務規則。

- **原子性（Atomicity）**：扣款與入帳一起提交，或一起回滾。
- **一致性（Consistency）**：交易前後仍符合約束，例如餘額不得為負、金額不應憑空增加。資料庫只會檢查已設定的約束；其他規則由應用實作。
- **隔離性（Isolation）**：多筆轉帳並行時，能看到哪些資料依隔離層級而定。兩筆同時讀取舊餘額再各自寫回，可能發生遺失更新；可用條件式原子 `UPDATE`、鎖定讀取或其他並發控制。
- **持久性（Durability）**：提交後的資料在資料庫承諾的故障條件與設定下可恢復；不表示硬體與副本全毀後也不需備份。

例如扣款可檢查「餘額至少 100」再更新，並確認實際更新了一列；若不成立就回滾。還要處理重試與重複請求，避免付款重送時扣兩次。
