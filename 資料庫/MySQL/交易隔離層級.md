# 交易隔離層級

隔離層級決定並行交易能看到哪些變更。以下以 MySQL 的 **InnoDB** 為準；普通 `SELECT` 的一致性讀取與 `SELECT ... FOR UPDATE` 等鎖定讀取，行為不同。

| 層級 | 普通讀取的重點 | 常見取捨 |
| --- | --- | --- |
| `READ UNCOMMITTED` | 可能讀到尚未提交的資料 | 可能髒讀 |
| `READ COMMITTED` | 每次一致性讀取建立新快照 | 同一交易重讀可能變動 |
| `REPEATABLE READ` | 預設值；沿用首次一致性讀取建立的快照 | 普通讀取穩定，但鎖定讀取須另外判斷 |
| `SERIALIZABLE` | 對並行讀寫施加更強限制 | 等待與死鎖可能增加 |

例如結帳頁同一交易重讀庫存：在 `READ COMMITTED` 下，其他交易提交後，第二次普通讀取可能看到新值；在 `REPEATABLE READ` 下，普通讀取通常仍看原快照。但 `UPDATE`、`DELETE` 與鎖定讀取會看較新的資料，不能把它們當成快照讀取。範圍鎖也可能影響插入。

依業務約束選隔離方式，並檢查是否混用普通與鎖定讀取；層級越高不代表應用邏輯就不用處理併發。

參考：[MySQL 8.4：InnoDB 隔離層級](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)、[一致性讀取](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)。
