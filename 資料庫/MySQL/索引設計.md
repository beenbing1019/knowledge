# 索引設計

索引像書末目錄：能減少查詢掃描，但每次新增或更新資料也要維護目錄。因此索引應為**常用查詢**服務，不是每個欄位都加一個。

1. 找出常用、耗時的查詢，確認過濾、關聯及排序條件。
2. 用 `EXPLAIN` 查看掃描範圍與現有索引是否被使用。
3. 視條件設計複合索引。例如依顧客查最近訂單，可考慮 `(customer_id, created_at)`；順序會影響索引可用性。
4. 衡量索引大小、寫入成本與資料分布；新增後量測效益，移除無用或重複索引須先確認其他查詢沒有依賴。

InnoDB 一般索引採 B-tree，不能直接改建成使用者管理的 Hash 索引。定期重建索引也不是所有慢查詢的通用解法。先量測瓶頸，再動手。
