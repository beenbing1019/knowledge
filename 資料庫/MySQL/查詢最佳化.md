# 查詢最佳化

**問題**：訂單列表載入很慢。原因可能是掃描大量資料、索引不合適、排序成本高，也可能是連線等待；不能只憑感覺加索引。

1. 從慢查詢日誌與監控確認執行時間、頻率和資料規模。
2. 用 `EXPLAIN` 看掃描筆數、索引、關聯（JOIN）與排序；對照實際查詢結果。
3. 按過濾與排序條件調整索引，衡量寫入和儲存成本，詳見 [[索引設計]]。
4. 只取必要欄位，檢查不必要的關聯、子查詢及笛卡兒積。用分頁限制每次回傳量。
5. 檢查統計資訊、連線數與資料庫設定；結果可容忍延遲時才評估快取及失效策略。

例如 `WHERE customer_id = ? ORDER BY created_at DESC LIMIT 20` 若掃描全表，可檢查 `(customer_id, created_at)` 索引是否符合查詢。用實際資料測前後延遲；查詢、索引都調整後仍慢，再考慮硬體或架構擴充。
