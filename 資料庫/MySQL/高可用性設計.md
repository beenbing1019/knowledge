# MySQL 高可用性設計

**問題**：訂單資料庫主機故障，網站不能結帳。先定義可接受的中斷時間與資料遺失量，再設計切換；「有複本」不等於「能自動恢復」。

1. **複本與切換**：部署複本後，還要偵測故障、選出新主節點、切換客戶端路由，並防止舊主節點繼續寫入。非同步複製可能遺失尚未同步的交易。
2. **其他叢集方案**：Galera Cluster、Percona XtraDB Cluster 等提供不同複製與故障處理方式；一致性與切換行為依產品及設定測試，不能只看「同步」二字。
3. **監控與告警**：觀察可用性、錯誤率、複製延遲、磁碟及連線數。讓值班者知道何時需要介入。
4. **獨立備份**：誤刪資料會同步到複本。定期備份到獨立位置，並演練還原。
5. **故障演練**：模擬主節點當機或網路分割，檢查切換時間、資料差異與客戶端重連。

快取、索引和較快硬體可以改善效能，**不能代替**故障切換與備份。限制資料庫帳號權限及保護傳輸，避免另一種原因造成服務中斷。
