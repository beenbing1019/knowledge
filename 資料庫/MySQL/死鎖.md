# 死鎖

**問題**：兩筆轉帳同時要更新帳戶 A、B。交易 1 先鎖 A 等 B；交易 2 先鎖 B 等 A。雙方互等，誰都無法繼續，這就是死鎖（Deadlock）。

**原因與影響**：取得多個鎖的順序不同，加上交易長時間持鎖，增加相互等待機會。InnoDB 偵測到死鎖時，通常會回滾其中一筆交易；應用可能收到失敗訊息。

**降低與處理**：

1. 所有轉帳都依固定順序更新帳戶，例如先鎖編號較小者。
2. 縮短交易，不要在持鎖期間等待外部 API；檢查查詢索引以縮小鎖定範圍。
3. 辨識死鎖錯誤，**重試整筆交易**，而非只重試失敗的 SQL。重試要有限次並避免重複外部副作用。
4. 查死鎖日誌與鎖等待，找出衝突的語句與持鎖時間。

換成 `READ COMMITTED` 或開啟交易，都不能保證沒有死鎖。**鎖等待逾時不等於死鎖**：InnoDB 預設可能只回滾逾時語句，應用需明確決定回滾整筆交易。
