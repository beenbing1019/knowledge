# Set 與 Map

**集合（Set）**回答「某個值在不在？」；**映射（Map）**回答「這個鍵對應什麼值？」兩者用途不同。

| 結構 | 特性 | 例子 |
| --- | --- | --- |
| Set | 值不重複，常用於成員判斷與交集、聯集、差集 | 記錄已按讚的使用者編號，避免同一人重複計算 |
| Map | 每個鍵（key）對應一個值（value） | 用學號查姓名、用商品編號查價格 |

例如比對兩份活動名單的共同參與者，可求兩個 Set 的交集；要查某位參與者的報名資料，則用 Map。Set／Map 是抽象的使用方式，**不一定**都由雜湊表實作；也可能由樹實作，此時順序與操作成本不同。

## 怎麼選？

- 活動報名先判斷「這個編號是否報過名」：用 Set；要同時保存報名時間，改用 Map，以編號對應報名資料。
- 需要輸出排序後的學號：可選有序樹實作的 Set／Map，或先用雜湊實作收集再排序。前者維持順序但操作常為 O(log n)，後者適合以查找為主、偶爾排序的情境。

這是資料的**抽象介面**，不能單憑名稱斷定操作成本；要看語言的實作與是否保證順序。
