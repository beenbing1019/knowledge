# 堆與優先佇列

**優先佇列（Priority Queue）**不按排隊先後，而是先取出優先級最高的項目。**二元堆積（Binary Heap）**是常見實作，通常用陣列表示一棵完全二元樹。

- **最小堆（Min Heap）**：父節點不大於子節點，根是最小值。
- **最大堆（Max Heap）**：父節點不小於子節點，根是最大值；堆排序常用最大堆。

| 操作 | 二元堆積成本 |
| --- | --- |
| 看根節點 | O(1) |
| 插入並向上調整 | O(log n) |
| 移除根並向下調整 | O(log n) |
| 尋找任意指定值 | O(n) |

例如客服系統先處理緊急工單，可用優先佇列反覆取出最高優先級項目。**堆不是完整排序的陣列**；O(1) 只適用看根節點，找任意項目仍是 O(n)。Dijkstra 最短路徑也常使用優先佇列；更新優先級的方式依實作而異。

## 陣列中的堆如何運作？

把最小堆放在陣列 `[2, 4, 3, 9]`：根 `2` 最先取出；插入 `1` 後，與父節點交換直到到頂端。對從 0 開始的索引 `i`，左右子節點是 `2i + 1`、`2i + 2`。**只有父子大小受約束**，不能假設同一層由小到大。

- 緊急工單持續加入並取最急：使用堆實作的優先佇列，插入、取出各 O(log n)。
- 若要查「某張工單是否在佇列內」，堆的 O(n) 掃描不適合大量查找；可另配 Map 查位置，更新時維持兩份結構一致，或換其他索引。
- 同一優先級若必須先進先出，把到達序號一併當作比較鍵；堆本身不保證穩定順序。
