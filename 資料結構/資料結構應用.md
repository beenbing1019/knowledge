# 資料結構應用

**術語**：FIFO＝先進先出（First In, First Out）。

選資料結構前，先問「最常做的操作是什麼？」同一份資料，按編號查、按順序處理、或找最短路線，適合的結構不同。

| 常見情境 | 常用結構 | 為什麼 |
| --- | --- | --- |
| 購物車依商品編號更新數量 | 映射（Map） | 用鍵找到對應商品 |
| 活動名單避免重複報名 | 集合（Set） | 判斷是否已存在 |
| 客服任務依到達順序處理 | 佇列（Queue） | 先到先處理 |
| 緊急任務先處理 | 優先佇列（Priority Queue） | 先取最高優先級 |
| 檔案夾或郵件夾層級 | 樹（Tree） | 表示父子關係 |
| 社交關係或道路 | 圖（Graph） | 表示任意節點間的連結 |
| 搜尋引擎依詞找文件 | 倒排索引（Inverted Index） | 從詞反查包含它的文件 |
| 圖片、音訊或科學計算 | 陣列（Array）／矩陣 | 按位置存取大量數值 |

例如搜尋網站要找包含「資料庫」的文章：逐篇掃描所有文章成本高；倒排索引先記下詞出現在哪些文件，再取相關文件。倒排索引本身也要隨文章新增與刪除而更新。

這些是常見設計，不是產品的唯一實作。路由表可能使用前綴樹（Trie）做最長前綴比對；快取可能結合雜湊表與其他結構管理淘汰順序。依查詢、寫入與記憶體成本選擇。

## 同一需求的不同取捨

- 待辦工作依到達順序：FIFO 佇列；若有緊急等級，改用優先佇列，但同級工作要自行定義先後。
- 商品依編號查找：Map；若還需要依價格取前十名，可另維護有序結構，或在資料量小時查出後排序。多維護一份索引要付出更新與儲存成本。
- 路線只有「轉乘次數」：無權重圖可用廣度優先搜尋（BFS，Breadth-First Search）；每段路耗時不同且權重非負時，可用 Dijkstra。

先寫下常見讀寫操作、資料規模與是否要求順序，再決定結構；避免看到產品名稱就套用固定解法。

參考：[Open Data Structures](https://opendatastructures.org/ods-python/)。
