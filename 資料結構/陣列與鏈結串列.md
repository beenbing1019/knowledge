# 陣列與鏈結串列

陣列（Array）把元素連續存放；鏈結串列（Linked List）靠節點的指標串接。選擇前，分清楚「找到位置」與「在已知位置修改」。

| 操作 | 陣列 | 鏈結串列 |
| --- | --- | --- |
| 按索引讀取、修改 | O(1) | O(n)，需走訪 |
| 搜尋指定值 | O(n) | O(n) |
| 中間插入、刪除 | 通常 O(n)，需搬移元素 | 已知節點及前一節點時 O(1)；找位置仍 O(n) |
| 空間 | 連續配置，預留容量可能閒置 | 不要求連續配置，但每個節點多佔指標空間 |

例如要頻繁讀取第 100 項，陣列可直接定位；鏈結串列要從已知節點一路往後找。若已握有某節點及其前一節點，頻繁插入時鏈結串列才可能省去搬移。固定陣列無法直接擴容；動態陣列擴容時須複製元素。堆疊與佇列也能用陣列實作。

## 用文字看儲存方式

- 陣列 `[甲, 乙, 丙]`：三個元素依序佔用連續位置，已知起點與元素大小可直接計算第 `i` 個位置。
- 單向鏈結串列 `甲 → 乙 → 丙 → null`：每個節點存值及下一節點的參照；不保證位置連續。要找丙，從甲開始走訪。
- 在乙後面插入丁：若已握有乙的參照，只改變指向，成為 `甲 → 乙 → 丁 → 丙`；若只知道「在第二個值之後」，仍要先找對應節點。刪除也要有前一節點或適合的結構。
- 把 `13` 插入陣列 `[11, 12, 14, 15, 16]` 的索引 2：先將 `14, 15, 16` 向後移一格，再放入 `13`，得到 `[11, 12, 13, 14, 15, 16]`。在鏈結串列 `A → B → C → D` 刪除 `C`，已握有 `B` 時讓 `B.next` 指向 `D`；只有值 `C` 時仍要先走訪。

## 實務選擇

- 頻繁按索引讀取畫面元素：動態陣列有良好區域性；陣列尾端增加通常攤銷 O(1)，但擴容時要複製。
- 已持有節點且要在中間插入大量工作：鏈結串列可減少搬移；每個節點要額外儲存參照，也可能使快取效率變差。
- 需要隊首移除與隊尾加入：可用鏈結串列或環狀陣列，別每次刪除動態陣列首項、搬移全部元素。
